# Data model

PostgreSQL 17, schema `public`, created by the `InitialCreate` EF Core migration.

Table and column names are generated by `UseSnakeCaseNamingConvention()`, so C# `TargetSleepTime`
becomes `target_sleep_time` with no per-property mapping. Every timestamp is `timestamptz`; the
application only ever writes UTC.

## Overview

```
                    users
                      │ 1
        ┌─────────────┼─────────────┬──────────────┬───────────────────┐
        │ 1           │ *           │ *            │ *                 │ *
  user_settings  user_sessions  energy_checkins  refresh_tokens  idempotency_records
                                                                        │
                                                   sync_changelog ──────┘
                                                   (also FK to users)

  audio_tracks   — global catalogue, no owner
```

Every child table cascades on user delete.

## `users`

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | PK, UUIDv7, generated by the app |
| `email` | `varchar(320)` | yes | Apple releases it on first authorization only |
| `apple_user_id` | `varchar(255)` | yes | The Apple `sub` claim. Null while the account is a guest |
| `is_anonymous` | `boolean` | no | Default false. True for an unregistered guest |
| `created_at` | `timestamptz` | no | |
| `updated_at` | `timestamptz` | no | |
| `last_login_at` | `timestamptz` | yes | Moved forward by every successful token exchange |
| `deleted_at` | `timestamptz` | yes | Account tombstone; also set on a guest absorbed by a merge |

```sql
CREATE UNIQUE INDEX ix_users_apple_user_id ON users (apple_user_id)
    WHERE apple_user_id IS NOT NULL AND deleted_at IS NULL;
CREATE UNIQUE INDEX ix_users_email ON users (email)
    WHERE email IS NOT NULL AND deleted_at IS NULL;
CREATE INDEX ix_users_is_anonymous_last_login_at ON users (is_anonymous, last_login_at)
    WHERE is_anonymous = true AND deleted_at IS NULL;
```

Both unique indexes are **partial**, for the same two reasons: guests carry neither an Apple id nor
an email, and a deleted account must not permanently lock its identity out of signing up again. The
`deleted_at IS NULL` clause matters for merges specifically — an absorbed guest is tombstoned rather
than destroyed, and a tombstone must not occupy the identity.

The third index is the reaper's access path for retiring guest accounts that have gone idle. The job
that uses it is not written yet.

An account is a guest when `is_anonymous` is true, which in practice coincides with
`apple_user_id IS NULL`. The flag is stored rather than derived so that a future identity provider
does not turn "has no Apple id" into the wrong answer.

## `user_settings`

One row per account; `user_id` is both the primary key and the foreign key.

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `user_id` | `uuid` | no | PK / FK → `users.id` |
| `target_sleep_time` | `time` | no | Wall clock, default `22:30` |
| `target_wake_time` | `time` | no | Wall clock, default `06:30` |
| `caffeine_cutoff_hours` | `integer` | no | Default 8 |
| `digital_sunset_minutes` | `integer` | no | Default 60 |
| `haptic_enabled` | `boolean` | no | Default true |
| `sound_mix_config` | `jsonb` | no | See below |
| `updated_at` | `timestamptz` | no | Server-set; pull cursor |

```sql
CREATE INDEX ix_user_settings_updated_at ON user_settings (updated_at);
```

`time` rather than `timestamptz` is deliberate: "bed at 22:30" is a wall-clock intent that should
survive the user flying to another timezone.

### `sound_mix_config` shape

```json
{
  "masterVolume": 0.8,
  "fadeOutSeconds": 15,
  "layers": [
    { "soundId": "rain_heavy", "volume": 0.6, "enabled": true }
  ]
}
```

Mapped from the `SoundMixConfig` record through `JsonDocumentConverter<T>` plus
`JsonDocumentComparer<T>`. The comparer matters: EF Core cannot diff an arbitrary object graph, so
equality and hashing go through the serialized form and snapshots are deep copies. Without it, edits
to the object would not be detected as changes.

Adding a field to the mix needs no migration.

## `user_sessions`

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | PK, **client**-generated UUIDv7 |
| `user_id` | `uuid` | no | FK → `users.id` |
| `session_type` | `varchar(32)` | no | `focus_90`, `power_nap`, `nsdr`, `digital_detox` |
| `started_at` | `timestamptz` | no | Device clock |
| `ended_at` | `timestamptz` | yes | Null while in progress |
| `target_duration_seconds` | `integer` | no | |
| `actual_duration_seconds` | `integer` | no | |
| `completed_successfully` | `boolean` | no | |
| `interruptions_count` | `integer` | no | |
| `metadata` | `jsonb` | no | Free-form client telemetry, `{}` when empty |
| `client_created_at` | `timestamptz` | no | Never overwritten by the server |
| `updated_at` | `timestamptz` | no | Client revision stamp — the merge clock |
| `deleted_at` | `timestamptz` | yes | Tombstone |

```sql
CREATE INDEX ix_user_sessions_user_id_updated_at ON user_sessions (user_id, updated_at);
CREATE INDEX ix_user_sessions_user_id_started_at ON user_sessions (user_id, started_at);
```

The first index serves every sync pull; the second serves timeline and history queries.

`session_type` stores the wire string, not the enum ordinal, so renumbering a C# enum member cannot
silently reinterpret existing rows.

## `energy_checkins`

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | PK, **client**-generated UUIDv7 |
| `user_id` | `uuid` | no | FK → `users.id` |
| `score` | `integer` | no | 1–5, enforced by check constraint |
| `context` | `varchar(1000)` | yes | Free text |
| `tags` | `text[]` | no | Native Postgres array, `{}` when empty |
| `recorded_at` | `timestamptz` | no | Device clock |
| `updated_at` | `timestamptz` | no | Client revision stamp |
| `deleted_at` | `timestamptz` | yes | Tombstone |

```sql
ALTER TABLE energy_checkins ADD CONSTRAINT ck_energy_checkins_score CHECK (score BETWEEN 1 AND 5);
CREATE INDEX ix_energy_checkins_user_id_updated_at  ON energy_checkins (user_id, updated_at);
CREATE INDEX ix_energy_checkins_user_id_recorded_at ON energy_checkins (user_id, recorded_at);
```

The 1–5 bound is enforced in three places — the validator, the domain constants and this constraint —
because a sync endpoint accepts data written by a client the server does not control.

`tags` uses a real `text[]` rather than a join table or a JSON blob: it is a small, unordered label
set that is always read with its parent row.

## `audio_tracks`

Global catalogue with no owner.

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | PK, UUIDv7 |
| `title` | `varchar(200)` | no | |
| `category` | `varchar(32)` | no | `nsdr`, `soundscape`, `breathing` |
| `duration_seconds` | `integer` | no | |
| `audio_url` | `varchar(2048)` | no | Absolute CDN URL |
| `file_size_bytes` | `bigint` | no | For offline download budgeting |
| `is_premium` | `boolean` | no | |
| `version` | `integer` | no | Default 1 |

```sql
CREATE INDEX ix_audio_tracks_category_is_premium ON audio_tracks (category, is_premium);
```

`version` is the cache-busting handle: bump it when the file behind `audio_url` changes and both the
catalogue ETag and the client's on-disk copy invalidate. The index covers the listing filter and the
ETag aggregate.

Seeded with eight starter tracks by `DatabaseInitializer` when the table is empty.

## `sync_changelog`

Append-only audit of every mutation the sync endpoints applied.

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `bigint` | no | PK, `GENERATED ALWAYS AS IDENTITY` |
| `user_id` | `uuid` | no | FK → `users.id` |
| `entity_name` | `varchar(64)` | no | `UserSession` or `EnergyCheckin` |
| `entity_id` | `uuid` | no | The mutated row |
| `operation` | `varchar(16)` | no | `insert`, `update`, `delete` |
| `changed_at` | `timestamptz` | no | Server clock |

```sql
CREATE INDEX ix_sync_changelog_user_id_changed_at ON sync_changelog (user_id, changed_at);
```

A database-generated identity gives a strictly increasing sequence the app cannot get wrong. The
last-writer-wins tables only hold current state, so this is the only record of history.

This table grows monotonically and has no retention policy yet.

## `refresh_tokens`

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | PK, UUIDv7 |
| `user_id` | `uuid` | no | FK → `users.id` |
| `token_hash` | `varchar(64)` | no | SHA-256 hex of the token — the token itself is never stored |
| `expires_at` | `timestamptz` | no | |
| `created_at` | `timestamptz` | no | |
| `revoked_at` | `timestamptz` | yes | Set on rotation or revocation |

```sql
CREATE UNIQUE INDEX ix_refresh_tokens_token_hash ON refresh_tokens (token_hash);
CREATE INDEX ix_refresh_tokens_user_id_expires_at ON refresh_tokens (user_id, expires_at);
```

Storing only the hash means a database leak cannot be replayed against the token endpoint. Rotation
sets `revoked_at` rather than deleting, so reuse of a spent token is detectable.

## `idempotency_records`

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `user_id` | `uuid` | no | Composite PK part 1, FK → `users.id` |
| `key` | `varchar(128)` | no | Composite PK part 2 — the `Idempotency-Key` header |
| `endpoint` | `varchar(256)` | no | Rejects key reuse across paths |
| `request_hash` | `varchar(64)` | no | SHA-256 of the bound arguments |
| `response_body` | `jsonb` | no | Replayed verbatim |
| `status_code` | `integer` | no | Replayed verbatim |
| `created_at` | `timestamptz` | no | |

```sql
CREATE INDEX ix_idempotency_records_created_at ON idempotency_records (created_at);
```

The key is scoped by user, so two accounts cannot collide on a client-chosen string. The
`created_at` index exists for a retention sweep that is not written yet.

## Conventions worth knowing

**UUIDv7 everywhere.** Time-ordered keys keep inserts at the right edge of the B-tree instead of
scattering across it, and let a device mint a key offline. `Guid.CreateVersion7()` in .NET 9 does
this natively.

**Enums as strings.** `session_type`, `category` and `operation` store the same spelling the JSON API
uses, via `EnumWireConverter<T>`. Rows are readable in `psql` without a lookup, and the schema is
decoupled from C# ordinals.

**`jsonb`, not `json`.** Binary storage, so Postgres can index into it later without a migration.

**Soft delete, never `DELETE`.** Synced entities tombstone with `deleted_at` so peers converge. The
cascade FKs only fire on genuine account deletion.

## Inspecting the schema

Generate the full DDL without touching a database:

```bash
dotnet ef migrations script --idempotent --project src/RecoveryApp.Infrastructure --startup-project src/RecoveryApp.Api -o schema.sql
```

Or connect through pgAdmin at <http://localhost:5050>, or directly:

```bash
docker compose exec postgres psql -U recoveryapp -d recoveryapp -c '\dt'
```
